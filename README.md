# Каркас работы с агентом

Доменно-независимый каркас для разработки проектов с Claude Code. Правила и роли — в `CLAUDE.md`
(Claude Code читает его сам), команды проверки — `make help`, ограничения и хуки — в
`.claude/settings.json`.

## Как работать

Ваша консольная сессия — **управляющий**: она не планирует и не пишет код, а раздаёт работу двум
субагентам (`architect` думает, `developer` делает) и принимает операционные решения сама,
отчитываясь фактом. Все трое могут работать параллельно. Детали ролей, полномочий и жизненного цикла
задачи — в `CLAUDE.md`.

Весь интерфейс — три команды:

| Команда | Что делает |
|---|---|
| `/workflow:status` | Дашборд: указатель восстановления, очередь, идеи, агенты. Ничего не меняет. |
| `/workflow:idea <описание или файл>` | Отдаёт идею архитектору; вердикт по готовой идее выносит управляющий. |
| `/workflow:build [TASK_ID \| all]` | Отдаёт работу разработчику: пусто — продолжить или взять следующую; ID — конкретную; `all` — всю очередь. |

Остальное — обычными словами: «остановись и отчитайся», «пройди приёмку», «проведи ретро»,
«не расширяй scope, зафиксируй находку отдельной задачей».

Типовой цикл: `/workflow:idea …` → архитектор прорабатывает идею в `workflow/source/`, управляющий
выносит вердикт → `/workflow:build` → разработчик закрывает задачу с проверками и коммитами →
«пройди приёмку».

## Что где лежит

```text
CLAUDE.md            контракт: роли, полномочия, жизненный цикл задачи, границы
Makefile             все команды репозитория; каталог — make help
.claude/             агенты, слэш-команды, разрешения и хуки
scripts/             логика проверок и хуков (по одному скрипту на домен)
workflow/            план и состояние: roadmap, backlog, progress, source/ (идеи), tasks/ (карточки)
```

Хуки и строка статуса — тонкие адаптеры над make-целями (`hook-*`, `statusline`), так что вся логика
живёт в `scripts/` и видна через `make help`. Если хук что-то заблокировал — это стоп-условие, а не
препятствие для обхода. Личные настройки (например, `additionalDirectories` для соседних
репозиториев) — в негитуемом `.claude/settings.local.json`.

Полная локальная проверка: `make check`.

## Подключение к своему проекту

1. Скопируйте `CLAUDE.md`, `.claude/`, `scripts/`, `workflow/` и `Makefile` в проект.
2. Заполните `workflow/roadmap.md` — направление и этапы.
3. Переопределите в своём Makefile команды проверки: `UNIT_TEST_COMMAND`, `TARGETED_TEST_COMMAND`,
   `FULL_VERIFY_COMMAND`, `FORMAT_CHECK_COMMAND`.
4. Запустите `make check` и убедитесь, что гейт зелёный до первой задачи.
