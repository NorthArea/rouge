# Top-down Shooter

Учебный top-down шутер на Rust и Macroquad: игрок ходит по арене клавишами, целится мышью, отстреливает
волны врагов, подбирает аптечки и патроны. Как и предыдущие три игры репозитория, это не столько сама
игра, сколько повод разобрать следующий слой игрового фундамента: управляемое движение без инерции,
камеру и разницу между мировыми и экранными координатами, простейший AI и здоровье вместо жизней.

README написан для программиста, который знает программирование, но game development видит впервые:
дальше объясняется не язык и не синтаксис, а почему игра устроена именно так.

Правила: игрок ходит по арене клавишами `WASD`, целится и стреляет мышью, у оружия ограниченный запас
патронов и пауза между выстрелами. Враги одного типа идут к игроку по прямой; попадание пули убивает их
за несколько выстрелов и приносит очки. Контакт с врагом снимает здоровье, но не чаще, чем раз в
секунду. Убитые враги иногда оставляют аптечку или патроны. Волна кончается, когда врагов не осталось —
следующая начинается по `Space` и врагов в ней больше. При нуле здоровья — `GameOver`, `R` начинает всё
заново. Внешних файлов игре не нужно: всё нарисовано примитивами Macroquad, окно 960×600 не меняет
размер.

## Запуск

Игра открывается из общего меню репозитория одной командой из корня (`cargo run`) — пункт `SHOOTER`.
Для разработки самой игры её можно запускать и в обход меню, отдельным процессом:

```text
cargo run -p shooter
```

## Управление

| Клавиша / устройство | Действие |
|---|---|
| `W` / `A` / `S` / `D` | Движение по арене |
| Мышь | Прицеливание — игрок повёрнут в сторону курсора |
| ЛКМ | Выстрел (если есть патроны и истёк cooldown) |
| `Space` | В `WaitingToStart` начинает игру, в `WaveCompleted` начинает следующую волну |
| `R` | Начать игру заново — здоровье, счёт, патроны, первая волна |
| `Esc` | Возврат в меню; при отдельном запуске (`cargo run -p shooter`) возвращаться некуда, и окно закрывается |

Надписи на экране написаны латиницей намеренно: встроенный шрифт Macroquad не гарантирует
кириллических глифов, а проверить это автотестом нельзя — рендеринг в проекте не тестируется.

## Что видно на экране

Сверху слева — строка `Health … Ammo … Score … Wave …`, а по центру окна появляется сообщение
текущего состояния: `Press SPACE to start`, `Wave N\nPress SPACE to continue`,
`GAME OVER\nPress R to restart`. Во время игры (`Playing`) сообщения нет. Убитый враг на мгновение
оставляет растущий и гаснущий круг на своём месте. Во время неуязвимости после касания игрок рисуется
тусклее — так видно, что повторное касание сейчас не в счёт.

## Game loop и стадии кадра

Игра — это не программа, которая ждёт ввода и отвечает на него. Это цикл, который крутится
непрерывно, десятки раз в секунду, и каждый оборот целиком перерисовывает мир. В `src/lib.rs` стадии
кадра выписаны явно и всегда идут в одном порядке:

1. **Чтение ввода** — клавиатура, мышь, `Esc`/`R`.
2. **Delta time** — сколько времени занял предыдущий кадр.
3. **Обновление состояния** — вся игровая логика внутри `Game::update` (`src/game.rs`): движение,
   прицеливание, стрельба, AI врагов, попадания, контактный урон, pickups, переходы волн.
4. **Проверка столкновений** — выполнена внутри `Game::update`, отдельного шага в `lib.rs` для неё нет.
5. **Рендеринг** — мир рисуется в мировых координатах камерой, HUD и сообщения — поверх, в экранных.
6. **Следующий кадр** — управление возвращается Macroquad.

`src/lib.rs`, помимо чтения ввода, вызова `Game::update` и перевода позиции мыши в мировые координаты
(об этом дальше), отвечает только за отрисовку — она читает уже готовое состояние `Game` и ничего в
нём не меняет.

## Игрок: присвоенная скорость, а не инерция

Это первое и самое заметное отличие от Asteroids. Там корабль разгонялся тягой и продолжал лететь по
инерции после того, как клавиша отпущена. Здесь скорость **присваивается** из ввода каждый кадр:

```rust
pub fn update(&mut self, up: bool, down: bool, left: bool, right: bool, delta_time: f32) {
    let intent = movement_intent(up, down, left, right);
    self.position += intent * PLAYER_SPEED * delta_time;
}
```

Отпустил клавишу — игрок остановился в том же кадре, никакого «скольжения». `movement_intent`
нормализует вектор намерения (`normalize_or_zero`, а не `normalize()`) — иначе диагональное движение
из двух одновременно нажатых клавиш было бы в `√2` раза быстрее прямого, а нулевой вектор намерения
(противоположные клавиши вместе или полное отсутствие ввода) дал бы `NaN` вместо нуля.

## Камера и мировые/экранные координаты

Арена (1920×1200) в четыре раза больше окна (960×600), поэтому видна только её часть, и камера следует
за игроком. Здесь начинается то, чего не было ни в одной из трёх предыдущих игр репозитория: **разница
между мировыми и экранными координатами**.

Позиция игрока, врагов, пуль и pickup — это координаты в мире игры (арене). Позиция курсора мыши,
которую отдаёт Macroquad (`mouse_position()`), и всё, что рисуется после сброса камеры (HUD,
сообщения), — это координаты на экране (окне). Пока камера не двигалась бы (или арена совпадала бы с
окном), разницы можно было бы не заметить. Но камера следует за игроком и у краёв арены смещается, так
что «мир под окном» плавает относительно «экрана»: одна и та же точка окна в разные моменты указывает
на разные точки арены.

Перевод между ними — ровно в одном месте на весь крейт (`camera::screen_to_world`), и камера ставится в
очереди задач раньше прицеливания мышью нарочно: код, написанный в экранных координатах до появления
камеры, работал бы правильно ровно до первого кадра, когда камера сдвинулась, а дальше прицел начал бы
«косить» тем сильнее, чем дальше игрок от центра арены.

```rust
pub fn camera_center(player_position: Vec2, arena: Arena, screen_size: Vec2) -> Vec2 {
    let half_screen = screen_size / 2.0;
    vec2(
        player_position.x.clamp(half_screen.x, arena.width - half_screen.x),
        player_position.y.clamp(half_screen.y, arena.height - half_screen.y),
    )
}
```

Камера следует за игроком, пока он далеко от края арены, и останавливается у самого края — иначе она
показала бы пространство за пределами арены. `run()` считает `camera_center` один раз за кадр и
пользуется этим же значением дважды: чтобы перевести позицию курсора в мировые координаты для
прицеливания и чтобы поставить `Camera2D` перед отрисовкой мира.

```rust
set_camera(&Camera2D {
    target: center,
    zoom: vec2(2.0 / screen_size.x, -2.0 / screen_size.y),
    ..Default::default()
});
draw_arena(arena);
// … отрисовка мира …
set_default_camera();
draw_hud(&game); // уже в экранных координатах
```

`set_camera` действует, пока не вызван `set_default_camera` — всё, что рисуется между ними (арена,
игрок, враги, пули, pickups, эффекты), рисуется в мировых координатах и honestly двигается вместе с
камерой. Всё, что рисуется после `set_default_camera` (HUD, сообщение состояния), — в экранных, и
остаётся на месте независимо от того, где сейчас игрок. Перепутать порядок — частая ошибка: UI,
нарисованный при активной `Camera2D`, окажется в мировых координатах и уедет за край экрана вместе с
камерой.

## Прицеливание мышью

Три шага прицеливания названы в коде отдельно, потому что того явно требует задание:

```rust
pub fn aim_at(&mut self, cursor_world: Vec2) {
    let direction = cursor_world - self.position;
    let Some(normalized_direction) = direction.try_normalize() else {
        return;
    };
    let angle = normalized_direction.y.atan2(normalized_direction.x);
    self.aim_angle = angle;
}
```

`direction` — вектор от игрока к курсору в мировых координатах (курсор уже переведён из экранных).
`try_normalize()` возвращает `None` на нулевом векторе — курсор ровно на игроке не портит ориентацию,
а просто оставляет её прежней; наивная `normalize()` дала бы `NaN`. `facing()` — единственный переход
«угол → направление» на весь крейт, тот же приём, что `Ship::facing()` в Asteroids: через него
выражаются и направление выстрела, и рисунок ствола.

## Стрельба и пули

ЛКМ создаёт пулю у дульного среза (`Player::barrel_position()`), а не в центре игрока; направление
фиксируется в момент выстрела и не следует за курсором дальше. Между выстрелами действует cooldown —
таймер, уменьшаемый на `delta_time`. Пуля живёт ограниченное время и исчезает и по истечении этого
срока, и при выходе за арену:

```rust
pub fn is_outside(&self, arena: Arena) -> bool {
    self.position.x < 0.0
        || self.position.x > arena.width
        || self.position.y < 0.0
        || self.position.y > arena.height
}
```

Это второе видимое отличие от Asteroids: там пространство было замкнутым, и объект, ушедший за
границу, появлялся с другой стороны (`rem_euclid`). Здесь у арены есть настоящий край — пуля, ушедшая
за него, просто удаляется.

## Противник и chase AI

Один тип врага, простейшее преследование — вектор от врага к игроку, нормализованный и умноженный на
скорость и `delta_time`. Никакого обхода препятствий, никакого pathfinding: это прямое требование
задания, а не недоработка. Раскладка волны детерминирована — позиции считаются по номеру волны и
индексу врага, а не через `rand` (то же решение, что уже было дважды: выпадение бонуса Arkanoid и
раскладка волны Asteroids). Игроку разница не заметна: он не считает, сколько врагов убил или на каком
шаге раскладки находится.

## Столкновения: круг с кругом везде

Physics engine в проекте нет — проверка написана вручную, и она ровно одна на весь крейт:

```rust
pub fn circles_overlap(a_position: Vec2, a_radius: f32, b_position: Vec2, b_radius: f32) -> bool {
    let distance_squared = a_position.distance_squared(b_position);
    let radius_sum = a_radius + b_radius;
    distance_squared <= radius_sum * radius_sum
}
```

Ею пользуются четыре разные пары: пуля/враг, враг/игрок, pickup/игрок и удержание игрока с врагами
внутри арены. Сравниваются квадраты расстояния и суммы радиусов — без извлечения корня. В отличие от
Arkanoid, где всё было прямоугольниками (AABB), здесь все подвижные объекты рисуются кругами, и круг —
не упрощение, а честная форма их столкновения.

Попадание пули во врага обрабатывается так, чтобы каждая пара «пуля — враг» рассматривалась не больше
одного раза за кадр: пуля, уже попавшая в одного врага, не проверяется против следующих, а уже
погибший в этом кадре враг не может быть задет повторно, потому что удаляется из коллекции только один
раз, в конце обхода.

## Здоровье, контактный урон и неуязвимость

У игрока здоровье, а не три жизни, как в Asteroids, — это отличие сохраняется намеренно. Контакт с
врагом снимает фиксированный урон, но не каждый кадр: без cooldown неуязвимости враг, стоящий на
игроке, снимал бы здоровье шестьдесят раз в секунду, и игра заканчивалась бы быстрее, чем игрок успел
бы понять, что произошло.

```rust
tick(&mut self.invulnerability_timer, delta_time);
self.check_player_collision();
```

Таймер неуязвимости тикает отдельным шагом до проверки касания, а не внутри неё: при большом
`delta_time` (когда неуязвимость истекает в этом же кадре) значение уходит в отрицательное, и та же
проверка в том же кадре уже пропускает касание — не приходится ждать ещё один кадр, чтобы игра снова
могла засчитать урон. Несколько врагов, коснувшихся игрока одновременно, считаются одним касанием, а
не суммой по числу врагов.

## Боеприпасы

Запас патронов ограничен константой. Проверка запаса стоит до вызова создания пули, а не внутри него:
при нуле патронов ЛКМ не создаёт пулю и не запускает cooldown впустую — иначе игрок, у которого
кончились патроны, ждал бы окончания паузы между выстрелами без всякой причины.

## Pickups: Health и Ammo

Убитый враг иногда оставляет аптечку или патроны — детерминированно, от счётчика убитых врагов, а не
по броску кубика (то же решение, что и для раскладки волны, — см. «Противник и chase AI»). Подбор —
столкновение круг с кругом с игроком; `Health` поднимает здоровье, но не выше максимума, `Ammo`
добавляет патроны без потолка. Pickup исчезает по истечении времени жизни, чтобы арена не зарастала
теми, кого никто не подобрал.

## Волны

Волна считается завершённой, когда врагов не осталось; следующая начинается по `Space` из
`WaveCompleted`, и врагов в ней больше. Счёт, здоровье и патроны переходят в следующую волну без
изменения — это поля матча, а не волны. Если игрок гибнет от касания в тот же кадр, когда умирает
последний враг, побеждает `GameOver`, а не `WaveCompleted`: контактный урон проверяется на ещё не
уменьшенной коллекции врагов, до того как попадание пули их коллекцию опустошит.

## Состояния игры

```text
WaitingToStart --Space--> Playing --последний враг мёртв--> WaveCompleted --Space--> Playing
                              |
                       здоровье <= 0
                              v
                          GameOver
```

`GameState` — обычный `enum` из четырёх вариантов, без state-machine framework, как и в трёх
предыдущих играх репозитория. Все переходы собраны в `Game::update` (`src/game.rs`) в одном месте.
Таймеров в игре ровно четыре: cooldown выстрела, время жизни пули, cooldown контактного урона
(неуязвимость) и время жизни pickup — каждый обычное поле `f32`, убывающее на `delta_time`; отдельной
системы таймеров в проекте нет, потому что четырём полям она не нужна.

## Чем эта игра отличается от Asteroids

| | Asteroids | Shooter |
|---|---|---|
| Движение игрока | тяга и инерция | скорость присваивается из ввода |
| Прицеливание | направление = направление движения | мышью, независимо от движения |
| Пространство | замкнутое (wrap) | арена с краем |
| Противник | нет | один тип, chase AI |
| «Жизни» | три жизни | здоровье (число) |
| Прогресс между волнами | только счёт и жизни | ещё и патроны, pickups |

Что осталось прежним — намеренно: никакого физического движка, никаких trait-иерархий, никакой
архитектуры под будущие игры. Код одной игры не проектируется под следующую: `Arena`, проверка круг с
кругом и перевод координат продублированы здесь, а не вынесены в общий крейт с тремя предыдущими играми
— повторение похожих сущностей в разных крейтах остаётся осознанной ценой того, что каждая игра
читается целиком.

## Устройство кода

| Файл | Что в нём |
|---|---|
| `src/main.rs` | `window_conf` и вызов `shooter::run()` — тонкая точка входа отдельного бинарника |
| `src/lib.rs` | `pub async fn run()`: окно, стадии кадра, чтение ввода, перевод курсора в мир, вся отрисовка |
| `src/game.rs` | `Game`, `GameState`, `Input`, `Effect`: всё состояние игры и все переходы между состояниями |
| `src/player.rs` | Игрок: движение, удержание в арене, прицеливание, ствол |
| `src/camera.rs` | Центр камеры и единственный перевод «экран ↔ мир» на весь крейт |
| `src/bullet.rs` | Пуля, cooldown выстрела: появление у ствола, время жизни, выход за арену |
| `src/enemy.rs` | Враг: chase AI, детерминированная раскладка волны |
| `src/pickup.rs` | `Pickup`, `PickupKind`, детерминированное правило выпадения, подбор |
| `src/collision.rs` | Единственная на крейт проверка круг-круг |
| `src/combat.rs` | Разрешение попаданий пуль по врагам за кадр, начисление очков |
| `src/score.rs` | Счёт |

Игровая логика получает delta time, арену и уже прочитанный ввод (`Input`) аргументами и не обращается
к состоянию Macroquad, поэтому вызывается из тестов без окна. Рендеринг, чтение клавиатуры и мыши не
тестируются: то, как выглядит окно и что происходит при нажатии клавиши, проверяется запуском игры, а
не автотестом.
