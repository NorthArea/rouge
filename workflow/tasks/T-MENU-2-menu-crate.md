# T-MENU-2: Крейт меню

## Статус

Главный статус, выбор задачи и состояние восстановления находятся в `workflow/progress.md`. Эта карточка
нужна для работы над одной задачей и удаляется после статуса `DONE`.

## Реализует

- `T-MENU-2` — крейт `menu`: список игр, курсор, выбор, вызов `run()`, возврат в меню, выход из
  программы; запуск одной командой; README.

## Цель

Одно приложение, одно окно: игрок запускает программу одной командой, выбирает игру в меню, играет,
возвращается в меню без закрытия программы, а `Esc`/`QUIT` в меню завершает процесс.

## Scope

- Крейт `menu` — третий участник workspace (`members` в корневом `Cargo.toml`), `#[macroquad::main]`
  живёт в нём, окно принадлежит ему.
- Чистая логика выбора (список пунктов `PONG`/`ARKANOID`/`QUIT`, курсор, перемещение с заворотом,
  подтверждение выбора, намерение выйти для `QUIT` и `Esc`) отделена от отрисовки и покрыта
  unit-тестами (D-10).
- Отрисовка примитивами Macroquad без внешних assets (D-01), латиницей (та же причина, что в Pong —
  кириллица встроенного шрифта не проверена наблюдением).
- `↑`/`↓` — курсор, `Enter`/`Space` — подтверждение, `Esc` в меню — выход, как и `QUIT` (D-23).
- `match` из трёх ветвей вызывает `pong::run().await`, `arkanoid::run().await` или завершает
  программу. Без trait, `Box<dyn Fn>`, таблицы игр (D-02).
- Меню не хранит игровых состояний; после возврата курсор остаётся на месте, повторный вход начинает
  игру заново (D-24) — эффект бесплатный, состояние матча живёт внутри `run()`.
- После возврата из `pong::run().await`/`arkanoid::run().await` меню сначала ждёт `next_frame().await`
  и только потом снова читает ввод — иначе то же нажатие `Esc`, которым вышли из игры, закроет
  программу (ловушка кадра возврата, D-23).
- Запуск одной командой: сначала пробуется `default-members = ["menu"]`; если `cargo run` без `-p` не
  запускает `menu` — фиксируется в отчёте с выводом команды, README называет `cargo run -p menu`.
  `Makefile` не редактируется (зона управляющего).
- Корневой `README.md` и README обеих игр называют новую команду запуска, сохраняя `cargo run -p <игра>`.

## Out Of Scope

Пауза внутри игры, экран настроек, громкость, сложность, мышь, анимации сложнее смены цвета, звук,
таблица рекордов, сохранение состояния игры между заходами в меню (D-24 отклоняет), показ управления
в меню, смена заголовка окна, автосборка списка игр (три пункта пишутся руками), любые изменения
игровой логики Pong/Arkanoid.

## Критерии приёмки

- [ ] `make check` зелёный по всему workspace (D-06).
- [ ] Чистая логика выбора покрыта unit-тестами: перемещение курсора с заворотом в обе стороны,
      подтверждение выбора, намерение выйти для `QUIT` и для `Esc`.
- [ ] Специальный gate (наблюдаемый прогон) — подтверждает владелец, не агент:
      1) одна команда → окно со списком, стрелки двигают курсор; 2) `Enter` на `PONG` открывает Pong;
      3) `Esc` в игре возвращает в меню, не закрывая программу (ловушка кадра возврата);
      4) курсор после возврата на том же месте; 5) `Enter` на `ARKANOID` открывает Arkanoid;
      6) повторный вход в Pong начинает матч заново; 7) `Esc`/`QUIT` в меню закрывает программу, до
      этого момента программа не закрылась ни разу.

## Проверка

```text
RED: make test-target TEST=<имя>
GREEN: make test
TARGETED: make test-target TEST=<имя>
FULL: make check
SPECIAL: наблюдаемый прогон окна — подтверждает владелец после остановки агента на этом гейте.
```

## Риски

- Ловушка кадра возврата (`is_key_pressed` перечитывает то же нажатие `Esc`) — не ловится unit-тестом,
  проверяется только наблюдением; риск снят требованием `next_frame().await` сразу после возврата из
  `run()`, до чтения ввода меню.
- Остаточное глобальное состояние Macroquad между двумя играми в одном процессе не наблюдалось заранее
  — проверяется тем же прогоном (вторая игра выглядит так же, как при отдельном запуске).

## Отчёт о завершении

Эта позиция несёт специальный gate. Агент останавливается после `make check` и наблюдаемой проверки со
своей стороны (то, что можно подтвердить без интерактивного окна), коммитит прогресс двумя коммитами
(задача + checkpoint), но НЕ помечает задачу `DONE`, не удаляет запись из backlog и не удаляет эту
карточку — ждёт подтверждения владельца по чек-листу.
