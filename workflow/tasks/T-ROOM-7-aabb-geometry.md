# T-ROOM-7: Геометрия комнаты как данные и пересечение AABB

## Статус

Главный статус, выбор задачи и состояние восстановления находятся в `workflow/progress.md`. Эта карточка
нужна для работы над одной задачей и удаляется после статуса `DONE`.

## Реализует

- `T-ROOM-7` — ID задачи из backlog.

## Цель

Стены и кубы-препятствия существуют не только в отрисовке, но и как коллекция коробок, а крейт умеет
отвечать, пересекаются ли две коробки.

## Scope

- `Aabb{min: Vec3, max: Vec3}` с конструктором «центр и половинные размеры».
- `Room` получает `Vec<Aabb>` — четыре стены и кубы — и уровень пола (уже есть `floor_level`).
- Функция пересечения двух `Aabb` — перекрытие по всем трём осям одновременно; касание — строгое
  сравнение (не пересекаются), решение исполнителя, зафиксировано тестом.
- Игрок получает половинные размеры и умеет выдавать свою коробку по текущей позиции.
- Отрисовка `T-ROOM-2` переводится на ту же коллекцию, чтобы видимое и просчитываемое не расходились.

## Out Of Scope

- Разрешение столкновений (`T-ROOM-8`).
- Вращающиеся/наклонные/невыпуклые препятствия, двери, подвижные части (D-46).

## Критерии приёмки

- [ ] две вложенные коробки пересекаются.
- [ ] две разнесённые не пересекаются.
- [ ] перекрытие по двум осям, разнесение по третьей — не пересекаются (по тесту на каждую ось).
- [ ] касание гранями — выбранный ответ зафиксирован тестом.
- [ ] коробка игрока строится из позиции и половинных размеров, движется вместе с ним.
- [ ] `make check` зелёный.

## Проверка

```text
Тесты вместе с реализацией (прецедент предыдущих позиций), закрытие изолирующими мутациями, sha256 сверяется.
TARGETED: make check
FULL: make check
SPECIAL: gate не назначен позиции.
```

## Риски

- Перепутанная ось в проверке пересечения — самый незаметный дефект; закрывается тестом на каждую ось отдельно.
