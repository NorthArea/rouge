# T-PONG-8: Аудит тестов и приёмка

## Статус

Главный статус, выбор задачи и состояние восстановления находятся в `workflow/progress.md`. Эта карточка
нужна для работы над одной задачей и удаляется после статуса `DONE`.

## Реализует

- `T-PONG-8` — аудит покрытия unit-тестами по D-10, полный набор проверок качества D-06 и подготовка
  приёмки владельцем.

## Цель

Подтвердить, что покрытие unit-тестами соответствует списку D-10, проект остаётся простым по D-02/D-07,
весь набор проверок качества зелёный, и передать владельцу пошаговый чек-лист наблюдаемой приёмки.

## Scope

- Аудит покрытия по шести пунктам D-10 с указанием конкретного теста на каждый пункт; недостающие
  тесты дописываются здесь.
- Аудит простоты: запрещённых конструкций D-02 нет, требования D-07 выполнены, обязательных внешних
  assets нет.
- Полный набор проверок качества D-06 (весь внутри `make check`).
- Пошаговый чек-лист наблюдаемой приёмки для владельца.

## Out Of Scope

- Новые игровые возможности.
- Рефакторинг ради красоты.
- Начало следующего учебного проекта (D-04).

## Критерии приёмки

- [x] По каждому из шести пунктов D-10 назван конкретный тест с именем и файлом.
- [x] Пробел покрытия, если найден, закрыт тестом с наблюдаемым RED.
- [x] Аудит простоты выполнен и записан.
- [x] `make check` → exit 0.
- [ ] Чек-лист наблюдаемой приёмки подтверждён владельцем (специальный gate).

## Результат аудита покрытия по D-10

Аудит выполнен по шести пунктам решения D-10. Пять пунктов покрыты полностью, в шестом найден пробел,
закрытый в этой задаче.

1. **Ограничение позиции ракетки границами** — `paddle_stops_at_the_top_edge`,
   `paddle_stops_at_the_bottom_edge` (`src/paddle.rs`). Дополнительно
   `paddle_moves_the_same_distance_regardless_of_frame_rate` и `paddle_without_input_does_not_move`
   закрепляют само перемещение. Пробелов нет.
2. **Начисление очков** — `ball_past_the_left_edge_scores_for_the_right_player`,
   `ball_past_the_right_edge_scores_for_the_left_player`, `ball_inside_the_field_scores_nothing`
   (`src/score.rs`); начисление в кадре — `a_goal_ends_the_round_with_the_point_scored`
   (`src/game.rs`). Пробелов нет.
3. **Reset мяча** — `reset_puts_the_ball_in_the_center_of_the_field`,
   `serve_direction_alternates_from_reset_to_reset` (`src/ball.rs`); сброс из кадра —
   `the_scored_point_starts_the_next_round_waiting` (`src/game.rs`). Пробелов нет.
4. **Изменение направления мяча** — `ball_bounces_off_the_top_edge`,
   `ball_bounces_off_the_bottom_edge`, `ball_inside_the_field_does_not_bounce` (`src/ball.rs`);
   само перемещение по вектору скорости — `ball_moves_by_velocity_times_delta_time` и
   `ball_moves_the_same_distance_regardless_of_frame_rate`. Пробелов нет.
5. **Расчёт отскока от ракетки** — `ball_bounces_right_off_the_left_paddle`,
   `ball_bounces_left_off_the_right_paddle`, `hit_at_the_paddle_center_sends_the_ball_almost_level`,
   `hit_above_the_paddle_center_sends_the_ball_up`, `hit_below_the_paddle_center_sends_the_ball_down`,
   `ball_missing_the_paddle_keeps_its_velocity`,
   `ball_already_moving_away_from_the_paddle_does_not_bounce_again`,
   `bounce_puts_the_ball_outside_the_paddle` (`src/ball.rs`). Пробелов нет.
6. **Переходы состояний игры** — `waiting_to_start_begins_playing_on_the_start_signal`,
   `a_goal_ends_the_round_with_the_point_scored`, `the_scored_point_starts_the_next_round_waiting`,
   `the_start_signal_does_not_skip_the_ball_returning_to_the_center`,
   `restarting_the_match_clears_the_score_and_waits`, `waiting_to_start_keeps_the_ball_still`,
   `paddles_move_while_waiting_for_the_serve` (`src/game.rs`).
   **Пробел.** Ни один тест не проходил кадр в состоянии `Playing` без гола, поэтому переход
   `Playing → PointScored` был проверен только со стороны гола: безусловный выход из раунда весь
   набор тестов пропускал. Закрыт тестом `a_round_without_a_goal_keeps_playing` (`src/game.rs`).

## Результат аудита простоты

- **D-02.** Пять типов и ровно те, что разрешены: `Game`, `Paddle`, `Ball`, `Score`, `GameState`
  (плюс `Field` — размеры поля значением, чтобы игровая логика не обращалась к Macroquad, D-10).
  ECS, event bus, dependency injection, plugin system, собственного engine, generic entity framework
  и trait-абстракций в коде нет: `grep` по `trait `, `dyn `, `Box<dyn`, `impl Trait`, `<T`, `where `
  в `src/` — ни одного совпадения. Иерархии модулей нет: четыре плоских модуля рядом с `main.rs`.
- **D-07.** `unwrap()`, `expect(`, `panic!`, `static mut`, `lazy_static`, `once_cell` и `.clone()` —
  ни одного совпадения в `src/`. Глобального mutable state нет: состояние живёт в `Game`, созданном
  в `main`, и передаётся аргументами. Предупреждений не остаётся:
  `cargo clippy --all-targets --all-features -- -D warnings` внутри `make check` зелёный.
- **Assets.** Загрузки ресурсов нет: `grep` по `load_texture`, `load_sound`, `load_ttf`, `load_file`,
  `include_bytes` в `src/` — ни одного совпадения; в репозитории нет каталога ресурсов, а
  `Cargo.toml` содержит одну зависимость — `macroquad = "0.4.16"`. Всё оформление собрано из
  примитивов Macroquad, шрифт счёта и подсказки — встроенный (`None` в `measure_text`/`draw_text`).
- **Размер.** 527 строк продакшн-кода в пяти файлах (`ball.rs` 143, `game.rs` 99, `main.rs` 197,
  `paddle.rs` 58, `score.rs` 30) и 30 unit-тестов. Проект читается целиком.

GREEN: make test → exit 0 (30 passed)
TARGETED: make test-target TEST=game → exit 0 (8 passed)
FULL: make check → exit 0 (30 passed; внутри — cargo fmt --check, clippy -D warnings, cargo test,
      cargo build, все четыре в одной цепочке `&&`)

## Риски

- Дописанный тест живёт в `src/game.rs` рядом с продакшн-кодом; мутация для RED вносится в тот же
  файл, поэтому откат сверяется контрольной суммой, а не на глаз.
- Критерии 1, 2, 12 и 18 и всё визуально проверяемое агент не наблюдает: они отмечены как ожидающие
  владельца, а не как выполненные.

## Чек-лист наблюдаемой приёмки для владельца

Один прогон `cargo run` по шагам. Каждый шаг проверяет то, что автотестом проверить нельзя.

1. **Запуск.** `make check` уже зелёный, поэтому запуск: `cargo run`. Открывается окно 960×600
   с заголовком «Pong»: тёмный фон, светлая рамка по краю, пунктирная линия по центру, счёт `0` и `0`
   по обе стороны от линии, две светлые ракетки у боковых границ, квадратный мяч в центре, внизу
   надпись `PRESS SPACE TO SERVE`. (Критерии 1, 11.)
2. **Ракетки до подачи.** Не нажимая `Space`, подержите `W`, затем `S` — левая ракетка едет вверх и
   вниз. То же для `↑` и `↓` справа. Мяч при этом стоит в центре. (Критерий 2.)
3. **Границы поля.** Держите `W` до упора — левая ракетка встаёт верхним краем в рамку и дальше не
   идёт, за поле не выходит. Держите `S` до упора — то же снизу. Повторите для правой ракетки
   клавишами `↑` и `↓`. (Критерий 7.)
4. **Подача.** Нажмите `Space` — надпись исчезает, мяч уходит вправо и вниз, движение плавное.
   (Критерии 1, 3.)
5. **Верхняя и нижняя границы.** Дайте мячу дойти до верхней или нижней рамки — он отражается от неё,
   не залипает и не уходит за рамку. (Критерий 4.)
6. **Отскок от ракетки.** Подставьте ракетку под мяч серединой — мяч уходит обратно почти
   горизонтально. (Критерии 5, 6.)
7. **Угол от места попадания.** Отбейте мяч верхним краем ракетки — он уходит вверх; отбейте нижним
   краем — уходит вниз. Чем дальше от центра ракетки, тем круче угол. Мяч в ракетке не залипает.
   (Критерий 6.)
8. **Скорость мяча.** За несколько отскоков подряд мяч не разгоняется: скорость на глаз та же, что и
   после подачи. (Критерий 3.)
9. **Гол и счёт.** Пропустите мяч за левую границу — счёт справа становится `1`, мяч возвращается в
   центр, снова видна надпись `PRESS SPACE TO SERVE`. (Критерии 8, 9, 11.)
10. **Следующий раунд и чередование подачи.** Нажмите `Space` — начинается новый раунд, и мяч уходит
    в сторону, противоположную предыдущей подаче. Пропустите мяч за правую границу — теперь растёт
    счёт слева. (Критерии 8, 9.)
11. **Рестарт.** Нажмите `R` — счёт становится `0`:`0`, мяч и обе ракетки возвращаются в исходные
    позиции, игра ждёт подачи. Нажмите `R` ещё раз в середине раунда — то же самое. (Критерий 10.)
12. **Выход.** Нажмите `Esc` — окно закрывается. (Критерий 1.)
13. **Осмотр без запуска.** Прочитайте `README.md` целиком и `src/` целиком (527 строк, пять файлов):
    README объясняет игровые концепции, а код читается целиком за один присест. (Критерии 17, 18.)

Критерии 12 (нет обязательных внешних assets), 13–16 (`cargo test`, `cargo fmt --check`, `clippy`,
`cargo build`) закрыты аудитом и `make check` и наблюдения не требуют.
