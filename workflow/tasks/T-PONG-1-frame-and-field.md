# T-PONG-1: Каркас, окно и игровое поле

## Статус

Главный статус, выбор задачи и состояние восстановления находятся в `workflow/progress.md`. Эта карточка
нужна для работы над одной задачей и удаляется после статуса `DONE`.

## Реализует

- `T-PONG-1` — позиция 1 очереди: cargo-проект в корне, зависимость Macroquad, окно, game loop с явными
  стадиями кадра, отрисовка поля и пунктирной центральной линии, выход по `Esc`.

## Цель

`cargo run` открывает окно с нарисованным полем классического Pong, в коде явно виден game loop,
`Esc` закрывает игру.

## Scope

- `Cargo.toml` в корне репозитория (D-05), зависимость `macroquad`, `src/main.rs`.
- Точка входа с циклом кадра, где явно видны стадии из D-09: чтение ввода → вычисление delta time →
  обновление состояния → проверка столкновений → рендеринг. На этой позиции стадии могут быть пустыми,
  но должны быть видимы как структура прикладного кода.
- Отрисовка поля: однотонный фон, пунктирная центральная линия, границы поля.
- Размеры поля читаются из размеров окна и передаются в код игры значениями, а не глобальным
  состоянием (D-10).
- Выход из игры по `Esc`.

## Out Of Scope

- Ракетки, мяч, счёт, состояния игры, ввод кроме `Esc`, README.

## Критерии приёмки

- [ ] `make check` зелёный: `cargo fmt --check`, clippy с `-D warnings`, `cargo test`, `cargo build`.
- [ ] В `src/main.rs` стадии кадра из D-09 видны как структура прикладного кода.
- [ ] Специальный gate (подтверждает владелец): `cargo run` открывает окно, поле с пунктирной
      центральной линией видно, `Esc` закрывает игру.

## Проверка

Unit-тестов у этой позиции нет и не должно быть: всё поведение задачи — создание окна и отрисовка,
а D-10 прямо запрещает тестировать рендеринг и ввод. Покрытие не имитируется. RED здесь — уже
существующее наблюдаемое падение сборки из-за отсутствия cargo-проекта; GREEN — та же команда после
его создания.

```text
RED: make test  (наблюдалось в этой сессии, exit 2)
  - тестов нет; падает сама сборка → `error: manifest path ".../Cargo.toml" does not exist`,
    cargo вернул 101, make — 2
GREEN: make test
TARGETED: make test-target TEST=<нет тестов на этой позиции>
FULL: make check
SPECIAL: cargo run — наблюдаемый прогон, подтверждает владелец
```

## Риски

- Загрузка `macroquad` из crates.io требует сети и системных библиотек окна; отсутствие системной
  библиотеки — стоп-условие, а не повод ставить пакеты.
- Clippy с `-D warnings` может отклонить идиомы каркаса (например, неиспользуемые стадии кадра);
  ловится `make check` до коммита.

## Отчёт о завершении

Передать владельцу, затем удалить карточку. Постоянная запись остаётся в строке `progress.md`.

- изменённые файлы: `Cargo.toml`, `Cargo.lock`, `src/main.rs`, `workflow/progress.md`, эта карточка.
- команды проверки и коды завершения: `make test` → 2 (RED, до кода), `make test` → 0 (GREEN),
  `cargo build` → 0, `make check` → 0. Специальный gate `cargo run` не запускался.
- следующая задача и точное следующее действие: владелец запускает `cargo run` и подтверждает окно,
  поле и выход по `Esc`; после подтверждения T-PONG-1 закрывается, следующая позиция — `T-PONG-2`.
