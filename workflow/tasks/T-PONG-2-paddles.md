# T-PONG-2: Ракетки и управление

## Статус

Главный статус, выбор задачи и состояние восстановления находятся в `workflow/progress.md`. Эта карточка
нужна для работы над одной задачей и удаляется после статуса `DONE`.

## Реализует

- `T-PONG-2` — ракетки: модель, вертикальное движение через delta time, ограничение границами поля,
  управление `W`/`S` и `↑`/`↓`, отрисовка.

## Цель

Обе ракетки видны, двигаются вертикально с клавиатуры со скоростью, не зависящей от FPS, и не выходят
за границы поля.

## Scope

- Данные ракетки: позиция, размер, скорость.
- Чистая функция обновления позиции: новое положение = позиция + направление × скорость × delta time,
  затем ограничение верхней и нижней границами поля. Размеры поля и delta time — аргументы (D-10).
- Ввод: `W` — левая ракетка вверх, `S` — левая вниз, `↑` — правая вверх, `↓` — правая вниз.
- Отрисовка обеих ракеток контрастным цветом.

## Out Of Scope

- Мяч, столкновения, счёт, состояния игры, ограничение движения ракеток игровым состоянием.

## Критерии приёмки

- [ ] Ракетка, доведённая до верхней границы, останавливается на ней и не уходит выше.
- [ ] То же для нижней границы.
- [ ] 60 шагов по `1/60` дают то же положение, что 120 шагов по `1/120` (независимость от FPS).
- [ ] Ракетка без ввода не двигается.
- [ ] Обе ракетки нарисованы контрастным цветом, клавиши привязаны в стадии чтения ввода.

## Проверка

Каждый тест писался и запускался по одному циклу RED → GREEN. Порядок выбран так, чтобы каждый
следующий тест падал по своей причине на коде, который прошёл предыдущий цикл (триангуляция), а не на
отсутствующем каркасе: сигнатура `Paddle::update` существует с первого цикла, поэтому каждый RED — это
провалившееся утверждение о поведении, а не ошибка компиляции.

```text
RED (по одному циклу на тест, каждый запуск — `make test-target TEST=<имя>`, exit 2):
  - paddle_moves_the_same_distance_regardless_of_frame_rate → panicked at src/paddle.rs:62:
    «60 кадров по 1/60: y = 250, ожидалось 450» (движения не было вовсе).
  - paddle_without_input_does_not_move → panicked at src/paddle.rs:86:
    «секунда без ввода сдвинула ракетку: y = 450.00058, ожидалось 250» (перемещение не смотрело
    на направление; этот тест и заставил внести `direction` в формулу).
  - paddle_stops_at_the_top_edge → panicked at src/paddle.rs:98:
    «ракетка ушла за верхнюю границу: y = -149.99986, ожидалось 0» (ограничения не было).
  - paddle_stops_at_the_bottom_edge → panicked at src/paddle.rs:110:
    «ракетка ушла за нижнюю границу: y = 649.99994, ожидалось 500» (была ограничена только
    верхняя граница).
GREEN: make test → exit 0, 4 passed
TARGETED: make test-target TEST=paddle → exit 0, 4 passed
FULL: make check → exit 0
SPECIAL: специального gate у позиции нет; фактическое управление с клавиатуры подтверждается
наблюдаемым прогоном в `T-PONG-8`.
```

Привязка клавиш и отрисовка unit-тестами не покрываются: это ввод и рендеринг Macroquad (D-10).

## Риски

- Ракетка объявлена в отдельном модуле и использует тип поля из корня крейта: ошибка видимости или
  неиспользованное поле структуры ловится clippy с `-D warnings` внутри `make check`.
- Накопление f32 при 120 шагах даёт отличие в последних разрядах: тест независимости от FPS сравнивает
  положения с явно заданной погрешностью, а не на точное равенство.
