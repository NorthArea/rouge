# Открытый backlog

В этом файле находятся только неначатые работы: scope, приоритет, зависимости, порядок и ожидаемая
проверка. Текущий статус и результаты выполнения записываются только в `workflow/progress.md`.

Очередь реализует техническое задание владельца «Game 01 — Pong». Ограничения, обязательные для всех
позиций (стек, запрет лишних архитектурных конструкций, набор проверок качества, платформы), записаны
решениями D-01 … D-15 в `workflow/roadmap.md` и здесь не повторяются. Полный список критериев приёмки
владельца — в описании позиции `T-PONG-8`; каждая позиция называет номера критериев, которые закрывает.

## Очередь

Берите первую позицию, зависимости которой выполнены. Проверяйте зависимости в репозитории, а не
доверяйте таблице без проверки.

| Position | IDs | Scope | Depends on | Gate |
|---|---|---|---|---|
| 1 | `T-PONG-8` | Аудит покрытия unit-тестами по D-10, полный набор проверок качества и подтверждение всех критериев приёмки владельца. | `T-PONG-7` | Специальный: наблюдаемый прогон `cargo run` по чек-листу всех критериев приёмки (подтверждает владелец). |

Каркас проекта (cargo-проект в корне, Macroquad, окно, game loop, поле, выход по `Esc`), ракетки
(`T-PONG-2`), мяч (`T-PONG-3`), его отскок от обеих ракеток (`T-PONG-4`), счёт и возврат мяча в центр
(`T-PONG-5`), состояния игры с новым раундом и рестартом (`T-PONG-6`) и README продукта (`T-PONG-7`)
уже сданы, поэтому зависимости позиции 1 выполнены.

`Gate` — это дополнительная проверка, которой нет в обычном `make check`. Обычный `make check` уже
прогоняет весь набор проверок качества D-06 (`cargo fmt --check`, clippy, `cargo test`, `cargo build`),
поэтому специальный gate остался только там, где требуется наблюдаемый прогон игры. О специальном gate
нужно сообщить при начале задачи и запускать его только после обычной проверки. Если требуется решение
владельца, агент ждёт его и записывает ответ.

## Правила очереди

- Каждая открытая задача есть в упорядоченной очереди.
- У каждого ID очереди есть подробное описание, если только позиция специально не объединяет несколько ID.
- Завершённые записи удаляются после закрытия задачи.
- Заблокированные задачи и решения владельца не маскируются под готовую работу.

## Описание позиций

### `T-PONG-8` — аудит тестов и приёмка

**Цель.** Подтвердить, что все критерии приёмки владельца выполнены, а покрытие unit-тестами
соответствует ТЗ.

**Scope.**

- Аудит покрытия по списку D-10: ограничение позиции ракетки границами, начисление очков, reset мяча,
  изменение направления мяча, расчёт отскока от ракетки, переходы состояний игры. Недостающие тесты
  дописываются здесь; если пробелов нет, это фиксируется в карточке как результат аудита.
- Аудит простоты: проект остаётся маленьким и читаемым целиком, запрещённых конструкций из D-02 нет,
  требования D-07 к Rust-коду выполнены, обязательных внешних assets нет.
- Полный набор проверок качества D-06 и наблюдаемый прогон по чек-листу критериев.
- Проверка независимости скорости игры от FPS: на уровне логики она подтверждена тестами
  эквивалентности шагов в `T-PONG-2` и `T-PONG-3`, на уровне игры — наблюдаемым прогоном.

**Out Of Scope.** Новые игровые возможности, рефакторинг ради красоты, начало следующего учебного
проекта (D-04).

**Что покрывается unit-тестом.** Только дописанные по результатам аудита тесты; они обязаны сначала
упасть по своей причине. Критерии 1, 2, 12 и 18 подтверждаются наблюдением и осмотром кода, а не
тестом, и это записывается в карточке честно.

**Проверка.** `make check` — он прогоняет весь обязательный набор D-06 и каждая команда должна дать
код 0:

- `cargo fmt --check`;
- `cargo clippy --all-targets --all-features -- -D warnings`;
- `cargo test`;
- `cargo build`.

Затем специальный gate: наблюдаемый прогон `cargo run` по чек-листу ниже, результат подтверждает
владелец.

**Чек-лист критериев приёмки владельца.** Работа считается завершённой, только если:

1. `cargo run` запускает Pong — каркас и окно уже сданы и подтверждены владельцем, повторное
   подтверждение здесь.
2. Обе ракетки управляются с клавиатуры — `T-PONG-2`, подтверждение здесь.
3. Движение не зависит от FPS — `T-PONG-2` и `T-PONG-3` (тесты), подтверждение здесь.
4. Мяч корректно отражается от верхней и нижней границ — `T-PONG-3`.
5. Мяч корректно сталкивается с обеими ракетками — `T-PONG-4`.
6. Угол отражения зависит от места попадания в ракетку — `T-PONG-4`.
7. Невозможно вывести ракетку за пределы поля — `T-PONG-2`.
8. Работает подсчёт очков — `T-PONG-5`.
9. После гола начинается новый раунд — `T-PONG-5` и `T-PONG-6`.
10. Работает restart — `T-PONG-6`.
11. Отображается счёт — `T-PONG-5`.
12. Нет обязательных внешних assets — аудит здесь.
13. Проходят все тесты — `cargo test` здесь.
14. `cargo fmt --check` проходит — здесь.
15. `cargo clippy --all-targets --all-features -- -D warnings` проходит — здесь.
16. `cargo build` проходит — здесь.
17. README объясняет ключевые игровые концепции — `T-PONG-7`, сверка здесь.
18. Проект остаётся маленьким и понятным — аудит здесь.

**После этой позиции очередь пуста.** Следующий учебный проект не начинается (D-04): работа
останавливается, `NEXT_BACKLOG_ID` становится `none`.
