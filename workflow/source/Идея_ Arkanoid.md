# Идея: Arkanoid

Файл: `workflow/source/2026-08-13-arkanoid.md` — дата создания идёт в имя, по ней виден возраст идеи.

## Статус

`на решении у управляющего` — требований достаточно для реализации первой версии.

## Цель

Реализовать на Rust законченную учебную версию Arkanoid как второй этап изучения разработки игр после Pong.

Проект должен дать практическое понимание:

- коллекций игровых объектов;
- жизненного цикла объектов;
- нескольких типов сущностей;
- столкновений;
- счёта и жизней;
- игровых состояний;
- уровней;
- временных игровых объектов;
- организации простого игрового цикла.

## Ограничения

- Язык: Rust.
- Сборка и зависимости: Cargo.
- Графическая библиотека: Macroquad.
- Не использовать полноценный игровой движок.
- Не использовать physics engine.
- Не использовать готовую библиотеку collision detection.
- Все перемещения должны учитывать `delta time`.
- Внешние графические assets не обязательны — использовать примитивы Macroquad.
- Игровая логика должна оставаться простой и доступной для изучения.
- Не создавать универсальный framework для следующих игр.
- Не использовать ECS, event bus, dependency injection, plugin system или сложные trait-иерархии.
- Проверки проекта:
  - `cargo fmt --check`;
  - `cargo clippy --all-targets --all-features -- -D warnings`;
  - `cargo test`;
  - `cargo build`.

## Основной сценарий

1. Игрок запускает игру и видит ракетку, мяч, блоки, счёт, количество жизней и номер уровня.
2. Игрок запускает раунд клавишей `Space` и управляет ракеткой клавишами `A/D` или `←/→`.
3. Мяч движется по игровому полю, отражается от стен и ракетки и разрушает блоки.
4. За уничтоженные блоки игрок получает очки.
5. При падении мяча за нижнюю границу игрок теряет жизнь.
6. После потери жизни мяч возвращается к ракетке, а новый раунд запускается по `Space`.
7. После уничтожения всех разрушаемых блоков текущий уровень завершается.
8. Игрок переходит на следующий уровень.
9. После потери всех жизней игра завершается состоянием `GameOver`.
10. После прохождения последнего уровня игра завершается состоянием `GameWon`.
11. Клавиша `R` полностью перезапускает игру.

## Этапы реализации

1. **Игровое окно и основной цикл**

   - Запускается окно с игровым полем.
   - В коде явно виден цикл:
     `input → update → collisions → state update → render`.
   - Игра корректно получает `delta time`.

2. **Ракетка игрока**

   - На поле отображается горизонтальная ракетка.
   - `A/D` и `←/→` перемещают её влево и вправо.
   - Скорость движения не зависит от FPS.
   - Ракетка не выходит за границы игрового поля.

3. **Мяч**

   - На поле присутствует мяч с позицией и вектором скорости.
   - По `Space` начинается движение.
   - Позиция изменяется по принципу:

     `position += velocity * delta_time`

   - Мяч отражается от левой, правой и верхней границ.

4. **Столкновение с ракеткой**

   - Мяч корректно отражается от ракетки.
   - Направление отражения зависит от точки попадания.
   - Удар в левую часть направляет мяч левее.
   - Удар в правую часть направляет мяч правее.
   - Удар около центра направляет мяч преимущественно вверх.
   - После столкновения мяч не остаётся внутри ракетки.

5. **Обычные блоки**

   - На уровне появляется коллекция `Vec<Brick>`.
   - Мяч сталкивается с блоками.
   - При столкновении корректно определяется направление отскока.
   - Обычный блок уничтожается после одного попадания.
   - Уничтоженный блок перестаёт участвовать в update, collision detection и rendering.

6. **Типы блоков**

   - Реализовать простой `enum` с типами:
     - `Normal`;
     - `Strong`;
     - `Indestructible`.
   - `Normal` уничтожается после одного попадания.
   - `Strong` выдерживает два попадания.
   - Повреждённый `Strong` визуально отличается от неповреждённого.
   - `Indestructible` отражает мяч, но не уничтожается.

7. **Счёт**

   - За уничтожение блоков начисляются очки.
   - Например:
     - `Normal` — 100;
     - `Strong` — 200;
     - `Indestructible` — 0.
   - Текущий счёт отображается на экране.

8. **Жизни и потеря мяча**

   - Игра начинается с трёх жизней.
   - Выход мяча через нижнюю границу уменьшает число жизней на одну.
   - После потери жизни мяч возвращается к ракетке.
   - Игра ждёт `Space` перед следующим раундом.
   - При нуле жизней игра переходит в `GameOver`.

9. **Игровые состояния**

   - Использовать простой Rust `enum`.
   - Минимальные состояния:
     - `WaitingToStart`;
     - `Playing`;
     - `LifeLost`;
     - `LevelCompleted`;
     - `GameOver`;
     - `GameWon`.
   - Переходы между состояниями происходят только по определённым игровым событиям.
   - Не создавать отдельный state-machine framework.

10. **Уровни**

   - Реализовать минимум три небольших уровня.
   - Уровни отличаются расположением и типами блоков.
   - Конфигурация уровней хранится непосредственно в Rust-коде.
   - Не использовать внешний редактор, JSON или YAML.
   - Когда все разрушаемые блоки уничтожены, уровень завершается.
   - После последнего уровня устанавливается `GameWon`.

11. **Один тип бонуса**

   - Некоторые уничтоженные блоки с небольшой вероятностью создают падающий бонус.
   - Использовать только один тип бонуса: `Wide Paddle`.
   - Бонус падает вниз с постоянной скоростью.
   - При столкновении с ракеткой её ширина временно увеличивается.
   - По окончании времени эффект исчезает.
   - Не пойманный бонус удаляется после выхода за нижнюю границу.

12. **UI**

   - Во время игры отображаются:
     - `Score`;
     - `Lives`;
     - `Level`.
   - Для соответствующих состояний отображаются сообщения:
     - `Press SPACE to start`;
     - `LEVEL COMPLETED`;
     - `GAME OVER`;
     - `YOU WIN`.

13. **Тестирование игровой логики**

   - Добавить unit-тесты для чистой логики.
   - Проверить:
     - ограничения движения ракетки;
     - потерю жизни;
     - начисление очков;
     - уничтожение `Normal`;
     - повреждение и уничтожение `Strong`;
     - невозможность уничтожения `Indestructible`;
     - расчёт направления отскока от ракетки;
     - завершение уровня;
     - переход между уровнями;
     - `GameOver`;
     - `GameWon`;
     - полный reset игры.
   - Rendering и Macroquad API unit-тестами не покрывать.

14. **Завершение проекта**

   - В README объяснить:

     - жизненный цикл объектов;
     - collision detection;
     - игровые состояния;
     - уровни;
     - бонусы;
     - отличие этого проекта от Pong.
   - Выполнить полный набор проверок.

## Результат первой версии

Законченная однопользовательская версия Arkanoid с:

- одной управляемой ракеткой;
- одним мячом;
- тремя типами блоков;
- счётом;
- тремя жизнями;
- минимум тремя уровнями;
- одним типом бонуса;
- состояниями `GameOver` и `GameWon`;
- простым UI;
- unit-тестами игровой логики;
- README с объяснением изучаемых концепций.

Результат проверяется запуском:

```bash
cargo run
```

и прохождением:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build
```

Игру необходимо вручную пройти минимум до второго уровня и проверить потерю жизни, получение бонуса, `GameOver` и `GameWon`.
