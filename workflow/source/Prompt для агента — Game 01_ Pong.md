# Game 01 — Pong

Реализуй с нуля небольшую законченную игру **Pong**.

## Цель проекта

Это первый учебный проект в последовательном изучении разработки видеоигр.

Главная цель — не просто получить работающий Pong, а на простом проекте освоить фундаментальные игровые концепции:

- game loop;
- frame update;
- delta time;
- обработку пользовательского ввода;
- координаты в 2D;
- позицию и скорость;
- движение объектов;
- столкновения;
- отражение мяча;
- состояние игры;
- счёт;
- рендеринг.

Код должен быть достаточно простым, чтобы его можно было прочитать целиком и понять, как работает игра.

## Технологии

Используй:

- Rust;
- Cargo;
- Macroquad;
- Git.

Игра должна собираться и запускаться как минимум на:

- macOS;
- Linux.

Не используй игровой движок или дополнительные высокоуровневые framework'и.

## Gameplay

Классический Pong:

```text
+------------------------------------------+
|                    |                     |
|                    |                     |
|   █                |               █     |
|   █           ●    |               █     |
|   █                |               █     |
|                    |                     |
|                    |                     |
+------------------------------------------+

       0                          0
```

Есть:

- левая ракетка;
- правая ракетка;
- мяч;
- игровое поле;
- счёт двух игроков.

### Управление

Левая ракетка:

- `W` — вверх;
- `S` — вниз.

Правая ракетка:

- `↑` — вверх;
- `↓` — вниз.

Дополнительно:

- `Space` — начать игру / следующий раунд;
- `R` — начать матч заново;
- `Esc` — выход.

## Поведение мяча

Мяч:

- имеет позицию;
- имеет двухмерный вектор скорости;
- движется независимо от FPS;
- отражается от верхней и нижней границ;
- отражается от ракеток;
- после попадания за левую или правую границу приносит очко противнику;
- после гола возвращается в центр;
- новый раунд начинается после нажатия `Space`.

Направление первоначальной подачи должно чередоваться или выбираться случайно.

## Ракетки

Ракетки:

- двигаются только вертикально;
- не могут выходить за границы игрового поля;
- перемещаются независимо от FPS.

## Отскок мяча

Не ограничивайся простым:

```text
velocity.x = -velocity.x
```

при каждом столкновении.

Направление отражения должно немного зависеть от места попадания мяча в ракетку:

```text
верх ракетки
    ↗

центр
    →

низ ракетки
    ↘
```

Это нужно реализовать простой понятной математикой.

Не требуется физический движок.

## Состояния игры

Минимально нужны состояния:

```text
WaitingToStart
      ↓
   Playing
      ↓
 PointScored
      ↓
WaitingToStart
```

После `R`:

```text
Reset
 ↓
WaitingToStart
```

Не создавай сложную state-machine framework.

Используй простой Rust `enum`.

## Архитектура

Архитектура должна быть минимальной.

Допустимые основные сущности:

```text
Game
Player/Paddle
Ball
Score
GameState
```

Не создавай:

- ECS;
- event bus;
- dependency injection;
- plugin system;
- собственный engine;
- generic entity framework;
- сложную иерархию модулей;
- ненужные trait abstraction;
- premature abstraction.

Не проектируй код для будущих игр.

Этот repository содержит только Pong.

Принцип:

> Сначала самый простой корректный код, который хорошо объясняет фундаментальные механики игры.

## Game loop

Структура программы должна позволять явно увидеть:

```text
loop
 ├── read input
 ├── calculate delta time
 ├── update game state
 ├── detect collisions
 ├── render
 └── next frame
```

Если Macroquad скрывает часть цикла, структура прикладного кода всё равно должна ясно отражать эти этапы.

## Delta time

Все движения должны учитывать время между кадрами.

Принцип:

```text
position += velocity * delta_time
```

Изменение FPS не должно существенно менять скорость игры.

## Collision detection

Реализуй самостоятельно простые столкновения:

- мяч ↔ верхняя граница;
- мяч ↔ нижняя граница;
- мяч ↔ левая ракетка;
- мяч ↔ правая ракетка.

Не подключай physics engine.

Код collision detection должен быть достаточно простым для изучения.

## Графика

Не нужны внешние assets.

Используй примитивы Macroquad:

- прямоугольники;
- круг или квадрат для мяча;
- текст;
- линии.

Стиль — минималистичный классический Pong:

- однотонный фон;
- контрастные ракетки;
- контрастный мяч;
- счёт;
- пунктирная центральная линия.

Главное — gameplay, а не визуальное оформление.

## Тестирование

Не пытайся тестировать rendering.

Unit-тестами покрой чистую игровую логику там, где это разумно:

- ограничение позиции ракетки границами;
- начисление очков;
- reset мяча;
- изменение направления мяча;
- расчёт отскока от ракетки;
- переходы состояний игры.

Отделяй чистую игровую логику от Macroquad настолько, насколько это естественно.

Не создавай сложную архитектуру только ради тестов.

## Качество Rust-кода

Код должен успешно проходить:

```bash
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build
```

Не оставляй warnings.

Используй идиоматичный Rust.

Избегай:

- `unwrap()` без необходимости;
- глобального mutable state;
- ненужного `clone`;
- чрезмерного использования traits;
- чрезмерной универсальности.

## Критерии приёмки

Работа считается завершённой, только если:

- `cargo run` запускает Pong;
- обе ракетки управляются с клавиатуры;
- движение не зависит от FPS;
- мяч корректно отражается от верхней и нижней границ;
- мяч корректно сталкивается с обеими ракетками;
- угол отражения зависит от места попадания в ракетку;
- невозможно вывести ракетку за пределы поля;
- работает подсчёт очков;
- после гола начинается новый раунд;
- работает restart;
- отображается счёт;
- нет обязательных внешних assets;
- проходят все тесты;
- `cargo fmt --check` проходит;
- `cargo clippy --all-targets --all-features -- -D warnings` проходит;
- `cargo build` проходит;
- README объясняет ключевые игровые концепции;
- проект остаётся маленьким и понятным.

При любом выборе между:

```text
более абстрактно
```

и

```text
проще и понятнее
```
